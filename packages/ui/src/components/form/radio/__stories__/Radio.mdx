    # Radio

    The `Radio` component represents a single choice input. It is intended for use both as a standalone control and as part of a `RadioGroup` for mutually exclusive selections. Use `Radio` when you need a simple, accessible choice input; prefer `RadioGroup` when managing multiple related options since it centralizes state and keyboard behavior. The component accepts all standard HTML input attributes and supports both controlled (`checked` + `onChange`) and uncontrolled usage. Use the `name` prop to group radios and `value` to identify options.

    ## **FAQ**

    ### **When should I use a standalone `Radio` vs `RadioGroup`?**
    Use a `RadioGroup` when presenting multiple related choices where only one option may be selected; it centralizes state via `value` and `onChange` and ensures consistent keyboard navigation. Use a standalone `Radio` when the input represents a single choice or when you need to place radios in a custom layout not suited to direct children.

    ### **How do I control selection programmatically?**
    For a group, keep a `value` in state and pass it to `RadioGroup` with an `onChange` callback. For single radios, use the `checked` prop and `onChange` to control the element.

    ### **Accessibility notes**
    Ensure grouped radios share the same `name` attribute so assistive tech recognizes the set. Provide clear labels and avoid using color alone to indicate selection. Native radio inputs handle most keyboard interactions (arrow keys, tab), so keep markup semantic.
